智能工具柜边缘计算机工程 · 关键类图（分组折叠版）

这张图回答一个问题：边缘计算机这一套代码，是怎么把「上位机的一条识别指令」变成「一帧全柜实况」的。 图里只画跨层的关键依赖（共 18 条，线上直接标接口名），层内的协作关系用子舱归属表达，不再逐条画箭头。 类名、接口名、方法名全部取自 edge/ 下的真实代码。

  1. 先看左边一列：① 入口层只负责装配（new + 注入 + 返回，不写业务），② 控制层是唯一能同时看见三个模块的人，③ 模块层是 tcp / usb / recognition 三块互不引用的业务舱。
  2. 再看右边一列：④ 基础层是零实现契约（interfaces）、生命周期骨架（base）、平台适配（platform）、配置日志与对照表（infra）。
  3. 箭头的三种读法：实线蓝＝依赖/调用方向（线上写了接口名）；虚线黄空三角＝继承或实现；点线紫＝ModuleWiring 的 Callable 注入（不是 import）。
  4. 节点的三种颜色：深色渐变＝正常主链路；灰色渐变 + 白字 + 虚线框＝待上板 / 未启用；黄褐色＝旁路（缓存 / 降级 / 复用）；翠绿描边＝本轮新增的类。
  5. 最容易迷失的是那条数据流：右下角「数据流一条线」把它单独立了出来，照着 ①→⑥ 读一遍就通了；看不清时用工具条折叠子舱或聚焦某一层。
