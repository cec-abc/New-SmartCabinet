智能工具柜边缘计算机工程 · 识别主流程 与 周期帧 / 开柜闸门流程

这两张图回答两个问题：上位机的一条识别指令，是怎么变成一帧全柜实况的；上位机凭什么决定开不开柜。 图里所有类名、方法名、字段名与取值都取自 edge/ 下的真实代码与上位机协议原文，没有一处是凭空写的。

  1. 图 2 怎么读：中间那条蓝色主干就是识别请求走完的 18 步，从上往下读；主干之外是三类分支——黄色是结果分档与异常旁路，灰色虚线是还没上板的能力。
  2. 三档结果：命中且置信度够 → alert_type = none；命中但置信度不够 → low_confidence；没命中 → unknown 且工具号置空，但那一行照样要出现在清单里。
  3. 聚合在控制层：4 个采集线程各自只出本线程的货位，EdgeControl 收齐后按货位号排序去重才发一帧；某个线程失败按降级补齐，保证清单不缺货位。
  4. 图 3 怎么读：3 秒一帧的周期帧 → 上位机看 8 路相机状态 → 只要有一路不是 ok 就拒绝开柜。
  5. 待上板：灰色渐变 + 白字 + 虚线框的节点是尚未实现的能力（Linux/v4l2 后端、真实对焦下发、模型权重推理、照度与脏污判定），线上不会走到。
