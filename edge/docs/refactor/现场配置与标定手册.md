# 边缘机现场配置与标定手册

## 说明

本手册告诉现场工程师**具体改哪个文件、哪一句配置、改成什么**。所有配置集中在 `edge/config/config.ini`，货位与类别在 `edge/config/roi_binding.csv` 和 `edge/config/class_item_map.csv`。

硬件前提：8 个物理相机 = 4 层 × 每层左右 2 个；柜门关闭、灯光固定、固定机位；一个泡棉槽只放一个工具，同型号工具靠专属标识区分位置。

> 修改任何配置前先备份：`config.ini`、`roi_binding.csv`、`class_item_map.csv` 各复制一份带日期的副本。

---

## 第一步：改 `config.ini` 的通信地址

文件：`edge/config/config.ini`，`[tcp]` 节。

| 配置句（原文） | 现场改成 | 改错的后果 |
| --- | --- | --- |
| `host = 127.0.0.1`（第 9 行） | `host = <上位机实际 IP>` | 边缘机连不上上位机，周期帧发不出，上位机判离线 |
| `port = 9000`（第 10 行） | `port = <约定端口>` | 同上 |

其余 `[tcp]` 项（超时、退避、帧长、心跳）现场一般不动。

## 第二步：改 `config.ini` 的相机配置（最容易出错）

文件：`edge/config/config.ini`，`[usb]` 节。

**关键：代码把 8 个相机按"前 4 个 + 后 4 个"配对，不是相邻配对。**

| worker（对应层） | 左相机 | 右相机 | 该层拼出的全景上的货位（ROI 行） |
| --- | --- | --- | --- |
| 1 | CAM1 | CAM5 | `roi_01, roi_02, …` ——所有 `worker_id=1` 的行（该层每一个槽一行） |
| 2 | CAM2 | CAM6 | `worker_id=2` 的全部行 |
| 3 | CAM3 | CAM7 | `worker_id=3` 的全部行 |
| 4 | CAM4 | CAM8 | `worker_id=4` 的全部行 |

**关键理解（不要搞错）**：

- **一个 worker = 一层 = 左右两台相机拼成的一张全景 = 这一层上的多个货位（多个槽、多个 ROI 行）**，不是"一层一个货位"。
- 代码按 `worker_id` 把**属于本层的所有 ROI 行**取出来（`recognition_worker.py` 的 `row.workerId == self._workerId`），对这张全景**只推理一次**，然后**逐行**判定每个槽，一行产出一条清单项。所以一层有 12 个槽，就要配 12 行 ROI，代码会出 12 条清单项。
- 当前 `roi_binding.csv` 只有 4 行、`worker_id` 恰好是 1/2/3/4，这只是**占位样例**，看起来像"一层一个货位"——现场必须按每层实际槽位数改成多行。`roi_id` 只是行的唯一编号，和 worker 号没有对应关系；真正决定"这一行属于哪层"的是 `worker_id` 列。

**接线规则**：USB 口索引 1~4 必须接四层的**左**相机、5~8 接四层的**右**相机，且顺序与层号一一对应。接反了不会报错，但拼图左右颠倒、货位坐标全错。

| 配置句（原文） | 现场改成 | 说明 |
| --- | --- | --- |
| `camera_indices = 1,2,3,4,5,6,7,8`（第 22 行） | 按实际稳定索引填，如只有一层接 2 个则 `camera_indices = 1,5` | 必须偶数；3/5/7 路会在 `auto` 模式报配置错误 |
| `capture_mode = auto`（第 24 行） | 保持 `auto` | 偶数路自动判双摄 |
| `layer_mode = multi`（第 26 行） | 保持 `multi` | 8 路=4 worker；单层工装改 `single` |
| `frame_source = camera`（第 28 行） | 保持 `camera` | 绝不能现场留 `placeholder`（占位图会让所有货位判未识别） |
| `save_frames = false`（第 30 行） | 保持 `false` | 标定期临时改 `true` 存单图，标完改回 |

## 第三步：逐路实测对焦/变焦（画面糊的根因）

文件：`edge/config/config.ini`，`[usb]` 节，第 34、35 行。

当前值全是 `0.0`（`focus_positions = 0.0,...`、`zoom_positions = 0.0,...`），画面大概率是糊的。

操作：对每一路相机执行实验室脚本实测：
```
python edge/lab/manual_focus_test.py --device <相机索引>
```
把第 N 个实测焦点值填进 `focus_positions` 的第 N 位，变焦值填进 `zoom_positions` 第 N 位。焦点上限 125、变焦上限 1020。`focus_stable_ms = 200`（第 37 行）一般保持。

> 现场柜门关着、灯光固定，对焦一次标定后可长期稳定；换相机或重新装机后必须重做。

## 第四步：重标货位坐标 `roi_binding.csv`（最关键）

文件：`edge/config/roi_binding.csv`。

12 列表头：
```
roi_id,worker_id,drawer_id,position,tool_id,required_type,marker_id,confidence,rect_x1,rect_y1,rect_x2,rect_y2
```

当前四行是 **640×480 占位样例**（`(0,0)-(320,240)` 之类）、`worker_id` 恰好 1/2/3/4、`marker_id` 是 `mk_8821` 占位名，**必须全部重标**。现场按每层实际槽位数配置**多行**：同一个 `worker_id` 的所有行归同一层处理（一层 N 个槽就配 N 行），不要照抄这个"一层一行"的占位样例。

| 列 | 现场填什么 |
| --- | --- |
| `roi_id` | 唯一编号，如 `roi_01` |
| `worker_id` | 该货位属于哪一层（1~4），与第二步的 worker 对应 |
| `drawer_id` / `position` | 抽屉号 / 货位号，如 `A-01-01`，与上位机台账一致 |
| `tool_id` | 该货位工具编号 |
| `required_type` | 工具类型（如 hammer），严格确认启用时参与比对 |
| `marker_id` | **该货位专属标识的类别名**（见第五步），必须换成真实类别名 |
| `confidence` | 置信度门槛，默认 0.85 |
| `rect_x1/y1/x2/y2` | 该货位在**本层拼接全景图**上的轴对齐矩形像素坐标 |

**重标操作步骤**：
1. `config.ini` 第 42 行临时改 `save_panorama = true`；
2. 上位机发一次识别请求，边缘机会把每层全景图写到 `output/recog/w1~w4/`（文件名含 `_panorama_`）；
3. 用看图工具打开每张全景图，量出每个货位槽的矩形像素坐标（左上角 x1,y1，右下角 x2,y2）；
4. 填进 CSV 对应行；
5. 标完把 `save_panorama` 改回 `false`。

**注意**：坐标基准是"本层左右两相机拼接后的全景"，不是单张相机图。换相机分辨率后必须整表重标——代码已加尺寸护栏，坐标与全景明显不符时会记 error 并按未识别降级，不会静默放行。

## 第五步：配置类别组合 `class_item_map.csv`（位置 + 类型如何绑定）

### 先讲清核心概念：一行 ROI = 一个槽 = 位置 + 类型的绑定

`roi_binding.csv` 的**每一行同时定义了两件事**，缺一不可：

- **位置**：`rect_x1, rect_y1, rect_x2, rect_y2` —— 这个槽在本层全景上的矩形（X/Y 像素坐标），告诉系统"**去哪里找**"；
- **类型**：`marker_id` —— 告诉系统"**找什么**"，它通过外键连到 `class_item_map.csv` 里的类别组合。

代码先把 AI 检出的每个目标框与矩形比对：框必须**完整落在本行矩形内**才算"在这个槽里"；然后在这个槽里检查类别组合是否命中。两个条件都满足，这一货位才判"正确放入"。**位置和类型不在同一步生效，但写在同一行里绑定。**

### 字段对应表（哪个字段连哪个）

| 作用 | 在哪个文件哪一列 | 代码里叫什么 | 说明 |
| --- | --- | --- | --- |
| 位置（去哪找） | `roi_binding.csv` 的 `rect_x1/y1/x2/y2` | `rectX1/Y1/X2/Y2` | 本层拼接全景上的轴对齐矩形，`x1,y1` 左上角、`x2,y2` 右下角 |
| 类型键（外键） | `roi_binding.csv` 的 `marker_id` | `row.markerId` | 该货位专属标识名 |
| 类型值 | `class_item_map.csv` 的 `item_name` | 组合表的 value | 与 `marker_id` **完全相等**才关联上 |
| 类型定义 | `class_item_map.csv` 的 `class_names` | 组合表的 key | 模型需要**同时**检出的类别集合，逗号分隔、顺序无关 |

### `class_item_map.csv` 当前内容

文件：`edge/config/class_item_map.csv`，两列 `class_names,item_name`：
```
"hammer,red_label",mk_8822
"wrench,blue_label",mk_8821
"screwdriver,yellow_label",mk_8823
"pliers,green_label",mk_8824
```

含义：某货位的 `marker_id` 是 `mk_8822` 时，只有在这个货位矩形内**同时检出 `hammer` 和 `red_label`** 两个类别，才算命中。组合里的类别必须同时出现（子集包含，允许槽里还有其它检出物）。置信度取组合内各项的**最低值**。

### 端到端例子（把位置和类型串起来）

假设第 1 层（`worker_id=1`）全景上，槽 A-01-02 的矩形是 `(320,0)-(640,240)`，`roi_binding.csv` 对应行：
```
roi_02,1,A-01,A-01-02,C01-T0008,hammer,mk_8822,0.85,320,0,640,240
```
判定过程：AI 在全景上认出一个 `hammer` 框和一个 `red_label` 框，两个框**都完整落在 (320,0)-(640,240) 内** → 组合 `{hammer, red_label}` 命中 `marker_id=mk_8822` → 该货位上报 `position=A-01-02, tool_id=C01-T0008, alert_type=none`。

如果这两个框在别的格子（比如矩形在 (0,0)-(320,240) 的槽），它们不落在本行矩形内 → 本行判未识别，不会串格。

### 同型号不同标识怎么配（位置 + 类型都要给）

两个货位都放锤子，但贴不同颜色标识。**两行的 `required_type` 相同、`marker_id` 不同、矩形坐标也不同**：
```
# roi_binding.csv 中两行（都属于第1层 worker_id=1，但在全景上不同位置）
roi_02,1,A-01,A-01-02,C01-T0008,hammer,mk_8822,0.85,320,0,640,240
roi_03,1,A-01,A-01-03,C01-T0011,hammer,mk_8825,0.85,0,240,320,480
```
```
# class_item_map.csv 中两行
"hammer,red_label",mk_8822
"hammer,blue_label",mk_8825
```
这样红标锤子只在 `(320,0)-(640,240)` 这个槽命中、蓝标锤子只在 `(0,240)-(320,480)` 那个槽命中——**类型不同、位置也不同**。只改 `marker_id` 不给不同矩形是不行的，两个槽会抢同一片区域。**前提是模型能识别 `red_label`/`blue_label` 这些类别**（第六步）。

## 第六步：换上现场训练的权重

文件：`edge/config/config.ini` 第 43 行。

- 当前 `model_path = ./weights/yolov8n.pt` 是 COCO 预训练模型，**不认识锤子、电池、标识**，直接用会全部判未识别；
- 现场必须用包含您工具类别（hammer / red_label / blue_label 等）的自训练权重；
- 权重可放仓库根 `weights/` 目录（代码按"工作目录 → edge/ → 仓库根"三级解析）；
- 换权重后 `inference_backend`（第 48 行）要与权重格式对应：`.pt` 用 `ultralytics`、`.onnx` 用 `onnxruntime`、`.rknn` 用 `rknn`。

---

## 第七步：现场验证（按顺序，一步不过不往下）

1. **启动无报错**：运行边缘机，日志无 `CONFIG` 阻断。
2. **周期帧相机全 ok**：抓一帧 `periodic`，`camera_status` 里配置的每一路都是 `ok`；任一 `offline` 说明相机索引或接线不对。
3. **全景图核对**：按第四步存全景，确认每层拼图左右正确、没有明显拼接缝切在工具上、工具清晰。
4. **尺寸护栏**：如果日志出现"货位坐标疑似占位未重标"或"货位坐标超出全景"，说明第四步坐标没标对，回到第四步。
5. **识别清单**：上位机发一次识别请求，抓 `recognize_ack`，逐项看：
   - 每个货位都有一行（不缺货位）；
   - 放对工具的货位 `tool_id` 非空、`alert_type=none`；
   - 空货位 `tool_id` 空、`alert_type=none`；
   - 如果整帧全是 `unknown`，日志会有"整帧清单全为未识别"error——检查坐标、类别名、权重。
6. **上位机联动**：确认上位机把 `unknown` 当成"不能确认"处理（**这一条需要上位机侧配合**，否则识别失效会被当成"取出正确"放行）。
