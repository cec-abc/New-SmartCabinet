## A. 必须补的数据文件

- [ ] **roi_binding.csv**：当前 4 行是占位样例（marker_id=mk_8821~8824、坐标按 640×480 四象限）。生产必须按真实货位逐行填 12 列：`roi_id,worker_id,drawer_id,position,tool_id,required_type,marker_id,confidence,rect_x1,y1,x2,y2`。要点：①全柜每个货位一行、不省略；②货位号形如 `A-01-02`；③`marker_id` 必须与训练模型的 `className` **逐字相同**；④四角点坐标参照**拼接全景**（非单路图），换真相机后按实际分辨率重标；⑤`worker_id` 不得超过实际 worker 数。**不补的后果**：识别能力静默失效——进程照常启动、周期帧照发，但识别请求回空清单，上位机判"覆盖不全"。
- [ ] **class_item_map.csv**：当前 4 行仍是占位类别组合（hammer/red_label→mk_8822）。多类别货位需按现场训练类别填；组合查不到会回退单标志匹配。**不补的后果**：多类别货位无法折算，命中判断对不上。
- [ ] **weights/yolov8n.pt**：已在仓库（6.25MB），核对 `model_path` 指向它、`inference_backend=ultralytics`。**风险**：权重缺失时代码不 Fail-Fast、只记 error 回空结果——**识别静默失效**，务必用 `recognize_ack_probe` 确认日志无"模型权重不存在"。

## B. 必须现场标定/修改的配置（config.ini）

- [ ] **tcp.host / tcp.port**：`127.0.0.1:9000` → 真实上位机 IP / 约定端口。不改则边缘机永远连不上，退避重连无限循环，上位机始终判离线。
- [ ] **camera_indices**：当前 `1,2,3,4,5,6,7,8`。按现场物理相机索引与左右配对顺序改（Windows 多数从 0 起）。顺序即物理编号；错位会导致拼图左右颠倒、ROI 全部对不上、末路相机报 offline 被拒开柜。
- [ ] **focus_positions / zoom_positions**：8 路当前全 `0.0`。用 `python edge/lab/manual_focus_test.py --device N` 逐路实测找清晰点（焦点上限 125、变焦上限 1020），把值填进第 N 位。不改则 8 路都下发焦点 0，画面糊、识别率骤降。
- [ ] **require_roi_binding**：建议生产改 `true`——ROI 表配错/缺失时启动即 Fail-Fast，把问题挡在启动阶段（当前 `false` 会静默降级为空清单）。
- [ ] **min_confidence**（本轮新增）：默认 `0.85`，置信度门槛单一来源；如现场模型置信度分布偏移，只改这一处即可（CSV 每行 confidence 列可覆盖）。
- [ ] **capture_mode / layer_mode**：当前 `auto` / `multi`。偶数路（2/4/6/8）正常；奇数路（3/5/7）在 auto 下装配即报 CONFIG 起不来。若现场是奇数路，需定案（凑偶数或改 capture_mode=single）。
- [ ] **目录**：`log.dir`、`usb.save_dirs`、`recognition.save_dirs` 按部署平台设（Windows 相对路径 / 麒麟绝对路径）。生产 `save_frames=false`、`save_panorama=false` 时不产生图像，主要确保日志目录可写。
- [ ] **超时项**：`infer_timeout_sec=3.0`、`aggregation_timeout_sec=5.0`、`nms_iou_threshold=0.45` 按现场核对。
