# 边缘计算机通信监控（lab 工具）

一个带图形界面的**真实链路监控客户端**：连接运行中的边缘计算机，把它上报的周期帧、识别清单原样显示出来。**工具自己不生成任何数据**——周期帧是边缘机发的，识别清单是发了请求后边缘机回的，收到什么就显示什么，全部原文展开、不折叠。

## 一、核心原则

- 不生成周期帧：周期帧完全来自边缘计算机，工具只接收并显示。
- 不造识别清单：工具只下发 `recognize_req`，回什么就显示什么，条目与字段全量展示。
- 不修改、不折叠：报文日志和展示区都是收到的原始帧全文。

## 二、连接方式

边缘机在生产里是 **TCP 客户端，主动连上位机服务端**（见 `edge/modules/tcp/tcp_socket.py`）。界面因此提供两种模式：

| 模式 | 用法 | 说明 |
| --- | --- | --- |
| 监听等待连入（默认） | 填本机 IP（默认 `0.0.0.0`）和端口（默认 `9000`），点“连接” | 符合生产协议；启动边缘机程序后它会主动连进来 |
| 主动连接边缘机 | 填边缘机的 IP 和端口，点“连接” | 仅当边缘机侧开了 TCP 服务端时使用 |

连上后状态栏显示“已连接”，周期帧每 3 秒自动刷新（是边缘机真实上报的）。

## 三、界面分区

| 区域 | 说明 |
| --- | --- |
| 连接边缘计算机 | IP、端口、模式、连接/断开按钮、链路状态 |
| 发送识别请求 | 填 request_id 点发送；只发请求，清单由边缘机返回 |
| 周期帧（原样全量） | 显示收到的 `periodic` 字段摘要 + 原始帧全文 |
| 识别清单（原样全量） | 表格显示收到的 `recognize_ack.items`，表头取收到条目的字段 + 原始应答全文 |
| 报文日志 | 每帧完整原文，`下发 TX` 蓝色是工具发出，`上报 RX` 绿色是边缘机上报 |

## 四、启动

工作区根目录执行（Python 3.9+）：

```
python -m edge.lab.host_comm_sim.simulator_gui
```

## 五、字段口径

帧字段与生产代码一致（详见 `protocol.py`，改生产协议时同步此处）：

- 周期帧 `periodic`：`type` / `uptime_sec` / `software_version` / `camera_status`（元素 `camera_id` + `status`，取 `ok` / `offline`）。
- 识别请求 `recognize_req`：`type` / `request_id` / `timestamp`。
- 识别应答 `recognize_ack`：`type` / `request_id` / `items`，条目字段 `position` / `tool_id` / `confidence` / `alert_type`。
- 序列化：紧凑 JSON + 换行 `\n` 切帧，UTF-8。

## 六、边界

- lab 演示工具，不是生产代码，不接入 12 阶段重构验收，不改任何契约。
- 纯图形监控，不占除所填端口外的资源；不依赖相机与模型。
